# 仕様案: 日程確定とGmail案内

- 作成日: 2026-10-01
- ステータス: 公開済み、2026-10-05に本人から自動案内の動作成功報告。v109追加仕様は末尾参照。
- 追加条件: 自動課金されない範囲でのみ実装・有効化。無料プランと請求先未連携を確認するまで公開しない。正本: [課金リスクと無料運用条件](task-calendar-cost-safety.md)。無料枠超過時は停止し、有料化して継続しない。

## 確認済みの体験

- 相手が候補日時・メールアドレス・対面/オンラインを選ぶ。備考は任意。備考に先方のZoom等のURLも記載できる。
- オンライン時は、備考URLの有無に関係なくGoogle Meetを自動発行。先方URLでMeetを上書きしない。対面時は会場を案内し、Meetは発行しない想定。
- 備考はTaskARE予定のmemoとGoogleカレンダーのdescriptionに同じ内容で保存。相手のURLは「先方からの備考」、Meetは「TaskARE発行のGoogle Meet」と区別する。参加先を勝手に推定しない。
- Google連携中のアカウントのGmailから確定案内を自動送信。アプリを閉じていても確定・Meet作成・送信まで行う。
- 案内文は候補提示用とは別の設定。日時/形式/会場/Meet/備考/Googleカレンダー追加リンクを差し込む。相手は追加画面で保存を確認する。

## 構成案・安全性

既存の公開meetドキュメントとブラウザ内meetWatchだけでは閉じた状態の確定処理を保証できない。既存Google連携中継とは分離した予約用サーバーを実装。NESTのPhase変更ではなくアプリ内のバックエンド拡張。判断は[ADR](../../../docs/adr/20261001-taskare-booking-mail.md)、公開前の操作は[サーバー手順](../booking-worker/README.md)を正本とする。

- Google Calendar API + Gmail API。必要最小限のgmail.sendとアカウント照合用の認可を追加。送信元を入力値から偽装せず、連携アカウントと一致することをサーバーで確認。
- リフレッシュトークンは暗号化してサーバー専用に保存。ブラウザ/Firestoreの共有リンク/ログへ出さない。解除と失効に対応。
- メールと備考は公開取得可能なmeetドキュメントへ追加しない。オーナー認証と回答者専用の閲覧境界を設ける。
- 回答は候補の範囲内、1予約につき1確定を原子的に保証。レート制限、入力長制限、送信宛先の検証、不正利用防止を行う。
- Googleイベントは予約IDから安定したIDを作り、再試行で複製しない。Meetがpendingの場合は準備完了まで待って案内する。
- 送信成功・未送信・結果不明を区別。Gmail送信のタイムアウトは勝手に再送しない。履歴と手動再送確認を用意する。
- Googleカレンダーへの二重招待を避ける。自由な案内メールとGoogleの招待メールを別々に無条件送信しない。
- TaskAREは次回起動時にサーバーの確定結果を予約IDで取り込み、手入力メモを失わない。
- 旧リンクは旧フローを維持。新旧が同じ予約を処理しない。

## 公開・検証状況

独立Worker公開、Gmail API有効化、認証情報登録、接続先のPR #92マージ済み。本人から自動案内の成功報告あり。開発テストでは外部APIをモックとし、実ユーザーへの送信や予定作成は行わない。

ローカルではメール/備考/参加形式の受付、Meet/メールのサーバー処理、テンプレート編集、送信結果、明示再試行、予定取り込みを追加。Nodeテスト15件・SQLite workerdスモークテスト・画面テストで検証した。外部APIはモックであり、実送信成功を意味しない。

## 実装の境界

- 独立Workers FreeとSQLite Durable Object。単一オーナーのFirebase UIDを設定で固定。従来の`?meet=`と新しい`?booking=`を分離する。
- 日本時間の候補を最大5件、30日先まで。受付期限は最大7日。候補開始後は回答不可。保持件数50件、発行1日10件、Gmail送信試行1日10件。上限は翌日まで停止し有料へ迂回しない。
- 受付後はGoogle主カレンダーの重複を確認。ローカルにしかない予定はリンク作成時に照合し、後からの変更はアプリ起動時の同期に依存する。
- 確定処理は最大6回、Gmail送信は自動1回。HTTP応答不明/中断は送信結果不明として手動確認を必要とする。明示再送も1予約につき通算3試行まで。
- 回答者の控えトークンはブラウザ内だけに保存。公開URLの所持者にメール/備考/会議リンクを公開しない。トークン紛失時は主催者へ問い合わせる。
- 保存期限は最終候補の7日後。オーナーは期間内に取り込む。未確定リンクのみ取消可能。確定済み予定の変更/取消は従来のカレンダーで行う。

## 2026-10-05 追加仕様

- 既存機能の限定拡張。候補は通常リンク・自動案内とも最大5件。時間は既存の30/60/90分を維持し、本人希望の60分を引き続き選べる。
- 最初に相手へ共有する案内文は、確定後のGmail本文と別設定 `bookingInvitationTemplate` に保存する。`{{予定名}}` / `{{候補}}` / `{{リンク}}` を置換。リンクを省いた文面でもURLを末尾に必ず添える。
- 発行直後と発行履歴から「案内文とリンクをコピー」。発行直後には全文を確認でき、URL単独コピーも残す。初回案内を勝手にメール送信する機能は追加しない。
- 既存の重複防止を維持。TaskAREの予定はアプリ表示中の同期で候補を停止する。公開フォーム読込後のリアルタイム更新ではない。Google primaryの重複は回答後・予定作成前に再確認し、重複時は処理を停止。全カレンダーやアプリ終了中の未同期ローカル予定は保証対象外。
