# 大切な日の通知サーバー

**未デプロイ。アプリのPRをマージしただけではスマホに通知は届きません。**
個人1名・最大10端末向けの専用Workerです。既存の `task-calendar-api`、Firebaseのルールや料金プランは変更しません。別の人と接続キーを共有しないでください。

## 初期設定

このディレクトリで実行します。CloudflareアカウントとNode.jsが必要です。有料プランに切り替える必要はありませんが、無料枠の上限超過時は配信失敗となります。実際のCPU時間・配信結果をダッシュボードで確認してください。

1. `npm ci`、`npx wrangler login` で接続。
2. `npx wrangler kv namespace create REMINDERS` で専用KVを作成。
3. `wrangler.example.jsonc` を `wrangler.jsonc` に複製し、KVのid、公開アプリのオリジン（URLのパスは除外）、連絡先メールを設定。設定ファイルはGit管理対象外。
4. `node generate-keys.mjs` で鍵を生成。既存ファイルは上書きしません。`.push-secrets.json` は権限600で生成され、Git管理対象外です。
5. `npm test`、`npx wrangler deploy --dry-run` で検証してから `npm run deploy`。
6. `npx wrangler secret bulk .push-secrets.json` で秘密情報を登録。鍵をチャットやGitHubに貼らないでください。
7. 公開済みアプリをHTTPSで開き、「設定 → 大切な日の通知」でWorkerのURLと `.push-secrets.json` の `PUSH_ADMIN_SECRET` を端末側に入力。
8. iPhoneはホーム画面に追加したアプリから「この端末の通知を登録」を押し、通知を許可。「通知予定を更新」と「テスト通知」で送信・受信を確認。
9. アプリを閉じている状態でもテスト通知が届くこと、翌日のCron実行で届くことを実機確認して完了。ここまで未確認なら「配信稼働済み」としない。

## 日常の利用

- 記念日に通知日を複数選択。既存記念日は通知なしのままです。日付指定、毎年・毎月・一度だけに対応。
- 敬老の日など、固定日/第何月曜で決まる14祝日に対応。春分・秋分、振替休日、臨時の祝日変更は自動計算しません。日付指定で登録してください。2月29日や31日は存在する月/年のみ通知します。
- 配信は日本時間9時。9:15、9:30、9:45に失敗分を再試行。9:45以降の設定は翌日以降の対象通知に反映。通知の権限、端末の集中モード、ネット接続によって到着が遅れる場合があります。
- 同じ通知先には1日1回まとめて配信。通知に最大4件表示し、残りは件数表示。通知をタップして記念日画面を開けます。
- 接続設定済み端末で記念日を編集すると自動送信。接続設定していない端末で変更した場合は、設定済み端末にカレンダーを同期して「通知予定を更新」を押してください。日記編集やアプリ起動だけでは通知予定を上書きしません。
- 「通知予定を更新」は、この端末の記念日で**全登録端末の配信予定**を置き換えます。別端末の変更を先に同期してください。直前のサーバー内容を指紋で照合し、古い内容からの自動上書きを拒否します。ただしKVは結果整合性で、同時書込の厳密な排他制御はありません。複数端末から同時編集しないでください。
- 送信失敗時は未送信表示を残します。オフラインで保存した後は、オンラインで更新ボタンを押してください。アプリ内表示に残っていても、配信側の予定は最後に送信できた内容です。
- この端末の通知を解除すると、この通知先のみ削除。他端末は継続。通知許可や購読が失効した場合は再登録。VAPID鍵を再発行すると既存端末の再登録が必要です。

## データ・安全性

専用KVに通知名・日付・通知タイミング・ブラウザのPush購読情報・2日間の配信記録を保存。日記やプロフィールは送信しません。接続キーは端末の別localStorageにのみ保存し、Firebase同期やJSONバックアップには含めません。

Web Pushの暗号化は `@block65/webcrypto-web-push` v2を使用。送信先はApple/FCM/MozillaのHTTPSホストに限定し、リダイレクトを禁止。APIは専用キー認証、許可オリジン、50KB上限、予定100件上限を持ちます。秘密情報・通知先をログへ出しません。

KVの結果整合性により厳密な「必ず一度だけ」は保証しません。同じ日の通知タグを共通にして重複表示を抑えています。通知はベストエフォートで、重要な期限の唯一の通知手段にしないでください。

## 検証

`npm test` は架空データで日付境界・認証・古い予定の拒否・再送・期限切れ通知先・実際の暗号化生成を検証。`wrangler deploy --dry-run --config wrangler.example.jsonc` はクラウドへ公開せずバンドルを確認します。どちらも実機への到着確認の代わりではありません。
