# ADR: 日程確定メールを無料Workersと単一SQLite Durable Objectに分離する

- **日付**: 2026-10-01
- **ステータス**: 採用（公開・追加認可は別途確認）
- **関連**: [仕様](../../apps/task-calendar/specs/task-calendar-scheduling-mail.md)

## 背景

オーナーはアプリ終了中のGmail案内を希望し、課金リスクを排除できなければ不要と指定。既存のブラウザ処理では終了中に動かず、公開Firestoreへ回答者のメールを足すことも不適切。無料契約の実画面確認後「そのまま進める」承認を受けた。分類は既存TaskARE内のバックエンド拡張であり、NESTのPhase構成は変更しない。

## 検討した選択肢

- Firebase Functions: Blazeを必要とするため採用しない。
- 既存Notion Workerへの混在: 認可・障害の影響範囲が広がるため採用しない。
- 独立Workers Free + SQLite Durable Object: 既存無料契約で原子的予約とアラームによるバックグラウンド処理が可能。

## 決定

独立Worker、単一オーナー・単一Durable Objectを採用。従来のmeetリンクは変更せず、新しいbookingリンクだけを扱う。APIは既定無効。所有者はFirebase認証とUID制限で識別、追加Google認可はFirebaseのGoogle主体と照合し、更新トークンはAES-GCMで暗号化して保存。公開リンクは日時候補だけ、回答詳細は別の回答控えトークンで認可する。

保存件数・発行数・送信試行数・再試行に固定上限を置く。Google予定は安定IDで作り、Gmail送信直前に送信中を永続化。応答不明は自動再送しない。無料サービス制限時に有料へ切り替える経路は設けない。

## 影響

### 2026-10-04 公開時の認証分離

同じGoogleプロジェクト内に自動案内専用OAuthウェブクライアントを用意する。既存TaskareクライアントのシークレットやリダイレクトURIを変更せず、旧カレンダー連携への影響を避ける。Googleアカウントの同一性は従来どおりFirebaseのGoogle主体と照合する。専用認証情報の作成・登録は本人操作で行う。

- 既存Firestoreルール・リンクを変更せず導入できる。
- 単一オーナー向け。複数人向けサービスへの拡張は別判断。
- 無料枠の制限やGoogle障害では処理が保留/停止する。無料契約はコードから保証できないため公開前/契約変更時に実契約を確認する。
- Gmailの追加同意・API有効化・OAuth設定・秘密値登録・デプロイ・実送信検証はローカルテストとは区別する。
