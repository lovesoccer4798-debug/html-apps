# ADR: 計測モードを追加し、Notionのまとめ送信を10日間に限定する

- **日付**: 2026-09-20
- **ステータス**: 採用
- **関連**: [v102仕様](../../apps/task-calendar/specs/task-calendar-v102.md)

## 背景（Context）

オーナーから、所要時間なしのタイマー・カウントアップ、最近10日のNotion同期、プロフィールの所属編集、テーマ追加の実装依頼を受けた。既存TaskAREの拡張として扱い、ワークスペースのPhaseは変更しない。

## 検討した選択肢

- タイマーの別実装と別保存領域を作る: 復元や完了記録が二重化する。
- 既存 `running` を拡張する: 現在のタイマー制御・保存・完了記録を利用できる。

## 決定（Decision）

`running.mode` に `countup` を追加。未指定は従来のカウントダウン。`elapsedMs` は停止までの累積、`segmentAt` は最後に再開した時刻とする。計測値は実時刻差から求める。完了後のタスク時刻・所要時間は既存の開始〜完了の実績記録（休憩込み・5分丸め）を維持。カウントアップでは終了を前提とする砂時計等の進捗表現を使わず、基本の時計表示を使う。

Notionの自動/手動まとめ送信は今日から9日前までを新しい日順に最大10日確認。成功時だけ指紋を保存し、失敗しても残りの日を送る。失敗日と簡潔なエラーをローカル設定に記録する。予定タイトルは既存の「メモ」プロパティへ含め、WorkerとNotionのスキーマ変更は不要とする。

## 影響（Consequences）

既存データの移行・削除は不要。10日より古い記録はまとめ送信の対象から外れる。カウントアップの計測表示は休憩を除き、予定に記録する時間帯は休憩を含むため一致しない場合がある。本番Notionの疎通は別途確認が必要。
